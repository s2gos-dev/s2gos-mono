# Deployment Guide

This document covers how to build and deploy the s2gos Docker image used by Airflow KubernetesPodOperator (KPO) tasks.

---

## Overview

Each workflow step runs inside a Docker container on Kubernetes, launched by Airflow's KPO. The image is built locally and pushed to `quay.io/s2gos/s2gos-mono`.

The build pipeline has three parts:

1. **`build_docker_image.py`** — uses `appligator` to generate the `image/` build context (Dockerfile, packages, data files), then applies local patches
2. **`image/`** — the Docker build context sent to the daemon
3. **`appligator-config.yaml`** — controls the image tag, DAG name, k8s resource limits, and mounts

---

## Releasing a new version

### 1. Bump the version

Edit `appligator-config.yaml`:

```yaml
image_name: quay.io/s2gos/s2gos-mono:0.0.11  # increment patch version
```

### 2. Regenerate the build context

`run_step.py` is hand-maintained and will be overwritten by `appligator`. Back it up first:

```bash
cp image/run_step.py /tmp/run_step.py.bak
pixi run python build_docker_image.py
cp /tmp/run_step.py.bak image/run_step.py
```

`build_docker_image.py` does the following:
- Calls `appligator.airflow.gen_dockerfile.generate()` to produce `image/Dockerfile`
- Copies `pixi.lock` into `image/`
- Patches the Dockerfile to pin pixi to `0.67.2` and fix the pip invocation
- Copies the `packages/` tree into `image/packages/`

### 3. Build the image

```bash
docker build -t quay.io/s2gos/s2gos-mono:<version> image/
```

### 4. Push the image

```bash
docker push quay.io/s2gos/s2gos-mono:<version>
```

## Build context layout (`image/`)

| Path | Description |
|------|-------------|
| `Dockerfile` | Generated by appligator, patched by `build_docker_image.py` |
| `run_step.py` | Hand-maintained entrypoint — **never overwrite** |
| `packages/` | Local Python packages (s2gos-utils, s2gos-generator, s2gos-simulator, s2gos-apps) |
| `pixi.lock` | Locked environment — ensures reproducible installs |
| `pyproject.toml` | Pixi project definition |
| `generator_resources/` | Contents of `packages/s2gos-generator/resources/data` — copied to `/opt/pixi/packages/s2gos-generator/resources/data` in the image |
| `extra_data/` | Vegetation XML files, meshes, spectra, and other runtime assets — copied to `/opt/pixi/hypstar_data` in the image |

---

## Dockerfile stages

**Stage 1 (build):** installs the pixi environment and pip-installs all local packages into it.

**Stage 2 (runtime):** starts from `debian:bookworm-slim`, copies only the resolved environment from stage 1, then:
- Copies `run_step.py` as the entrypoint
- Copies `generator_resources` → `/opt/pixi/packages/s2gos-generator/resources/data`
- Copies `extra_data` → `/opt/pixi/hypstar_data`
- Runs `eradiate data install core gecko monotropa` to bake in eradiate datasets
- Smoke-tests with `import s2gos_apps`

---

## Runtime data paths

The container exposes two asset search paths, configured in `k8s/s2gos-settings-configmap.yaml` and mounted at runtime:

| Container path | Source | Purpose |
|---|---|---|
| `/opt/pixi/packages/s2gos-generator/resources/data` | `generator_resources/` in image | Materials, spectra, DEM/landcover indices |
| `/opt/pixi/hypstar_data` | `extra_data/` in image | Vegetation XML files, meshes, scenario-specific assets |
| `/opt/pixi/s2gos_settings.yaml` | `s2gos-settings` ConfigMap | Runtime settings (search paths, credentials, dataset paths) |
| `/mnt/output` | `s2gos-output-pvc` PVC | Workflow output files |

If an asset is not found at runtime, the error will list which paths were searched. Add the missing directory to `search_paths` in `k8s/s2gos-settings-configmap.yaml` or place the file in `extra_data/` and rebuild.

## appligator-config.yaml reference

```yaml
image_name: quay.io/s2gos/s2gos-mono:<version>  # image tag for KPO pods
dag_name: workflow_dags                           # Airflow DAG bundle name

secret_names:
  - s2gos-credentials                            # k8s Secret mounted as env vars

cpu_request: "2"
memory_request: "8Gi"
cpu_limit: "4"
memory_limit: "16Gi"

pvc_mounts:
  - name: s2gos-output
    claim_name: s2gos-output-pvc
    mount_path: /mnt/output

config_map_mounts:
  - name: s2gos-settings
    config_map_name: s2gos-settings
    mount_path: /opt/pixi/
    sub_path: s2gos_settings.yaml
```

After changing `image_name`, regenerate the DAGs:

```bash
pixi run python -m appligator
```

---

## Applying k8s config changes

To update the settings ConfigMap on the cluster:

```bash
kubectl apply -f k8s/s2gos-settings-configmap.yaml
```

Pods pick up ConfigMap changes on the next run (no restart needed since KPO spawns a fresh pod per task).
